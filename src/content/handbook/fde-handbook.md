title: "FDE 工作手册"
---

> 本手册把《前线部署工程师》全书的方法论整理成一份可执行的检查清单。
> 按"一次完整交付旅程"组织：问题筛选 → 客户筛选 → 激活部署 → 守住续约 → 扩大收入 → 规模化复制，外加度量层与道德底线。
> 每个阶段含：核心信条、决策清单、高危信号、关键产出物、阈值。
> 方括号 `[ ]` 是可勾选项；带 ❗ 的是书里标过的高危信号或红线。

---

## 使用说明

1. **不是线性流程，是并行回路**：六个阶段会重叠（你一边激活一边就在为续约攒证据；一边交付一边就在为复制沉淀资产）。
2. **每个项目盯 3-5 个核心指标**，不要铺满一面墙的仪表盘（见度量层）。
3. **基线数据在项目启动第一天采集——错过永不再来**。
4. **每个阶段的"拒绝机制"和"做下去"同等重要**。FDE 模式最重要的盈利能力，是拒绝错误的项目。
5. 手册中的阈值全部来自原书附录 A 或正文，标了"参考标准"的地方都是书里写明的数字。

## 全景图：FDE 交付旅程

```
Phase 0  入场自检          (我是不是该做 FDE / 该接这个客户)
   │
Phase 1  解决正确的问题     (写第一行代码之前)         ← 第2章
   │   └ PSF 三关检验 + 拒绝机制 + MVD
   │
Phase 2  赢得客户           (把验证过的价值变成合同)   ← 第3章
   │   └ 灯塔筛选 + 进场尽调五地图 + 通关三闸门
   │
Phase 3  激活部署           (上线 ≠ 激活)              ← 第4章
   │   └ 七件武器：热修复/评估体系/降门槛/集成/变革/自动化
   │
Phase 4  守住续约           (续约是生死线)             ← 第5章
   │   └ 防五类流失 + 有损服务 + 健康度体系
   │
Phase 5  扩大收入           (存量深耕 + 成果计价)      ← 第6章
   │   └ 登陆与扩张 + 价值度量系统
   │
Phase 6  规模化复制         (摆脱收入随人头线性增长)   ← 第7章
       └ 三级杠杆 + 产品化四问
```

## Phase 0 ｜ 入场自检

> 在你接任何一个项目之前，先回答三组问题。这决定你是不是在做 FDE，还是在做"挂着酷头衔的咨询"。

### 0.1 角色自检：我做的是真 FDE 吗？

- [ ] **我背后有没有平台底座？** 没有平台底座的 FDE = 纯人力外包。❗ 这是第一优先级。
- [ ] **现场学习怎么回流产品？** 能讲出一个"最近从现场沉淀为产品功能"的实例吗？讲不出来就有问题。
- [ ] **我向谁汇报？** 向产品/工程线汇报 = 模式被认真对待；向销售线汇报 = 警惕沦为售前人力池。
- [ ] **计价方式是否向结果靠拢？** 纯按人头/工时算钱 = 驻场外包，不是 FDE。
- [ ] **我做的定制工作是否随客户数递减？** 麦格鲁试金石：第 N 个客户的定制量应显著小于第 1 个。连续三个客户定制量不降，立即检视产品回流机制。

### 0.2 FDE ≠ 驻场外包 的三条区隔（国内服务商的官网定义）

- [ ] FDE 按阶段交付、按结果验收；驻场外包按工时结算。
- [ ] FDE 带着产品底座来做工程；驻场外包从零现写现改。
- [ ] FDE 做完会走，能力沉淀在系统和客户团队里；驻场外包越驻越久、人走系统停。

### 0.3 代价自检（从业者的诚实提醒）

- [ ] 我能接受 25%-50% 出差吗？（OpenAI 招聘启事明确写出差最高 50%）
- [ ] 我能接受工作节奏被客户的紧急程度定义吗？
- [ ] 我对职业倦怠的风险有预案吗？（Reddit 上 FDE 最大吐槽点 = 差旅与续航）

## Phase 1 ｜ 解决正确的问题（第 2 章）

> **核心信条**：在错误的问题上，一切执行力都是浪费；企业里错误问题的密度远超想象。
> 写第一行代码之前，确保你在解决正确的问题。

### 1.1 PSF 三关检验（问题与方案的契合）

> 对应 PMF，但视角从供给方转到需求方：问"客户这个具体问题值不值得、能不能被我们的能力解决"。

**第一关：痛点检验**
- [ ] 这是某个**具体的人**的**具体的痛**吗？（"提升客服效率"是方向不是痛点；"客服主管每周一花 3 小时从 4 个系统手动汇总升级工单"才是痛点）
- [ ] 它是不是 CEO 最关注的 5 个问题之一？（只有这个量级才能碾过企业内部官僚阻力）
- [ ] 既难又有业务影响吗？（只有难 = 炫技；只有影响不难 = 轮不到你）

**第二关：经济性检验**
- [ ] 这个问题每周吃掉多少人时？折合多少人力成本？
- [ ] 出错一次赔多少？省下来的人手能去干什么？
- [ ] 有量化靶子吗？（如"排产冲突降低 30%""库存周转缩短 15%"）
- [ ] ❗ 警惕"演示效果好的问题"vs"值钱的问题"——超半数预算投向前台销售营销，回报却在后台合同审查/采购/风控。

**第三关：可行性检验**
- [ ] 数据在哪？什么状态？（答案常比想象糟：分散在 7 个系统、3 个版本对不上、最权威那份在老员工私人表格里）
- [ ] 这个问题需要的准确率门槛是多少？（"99%可用"和"90%可用"隔着数量级工程投入；很多场景 90% + 人工复核就是最优解）
- [ ] 以我们现在的能力 + 这个客户的数据现实，能做到几分？

### 1.2 拒绝机制三防线

> FDE 成本结构是前置的——最贵的工程师、差旅、现场投入全发生在回款之前。拒绝错误的项目 = 最重要的盈利能力。

- [ ] **防线一：概念验证必须有"毕业标准"**。启动时就白纸黑字写明：多少周后、用什么指标、达到什么数值 → 毕业进付费部署；达不到 → 双方体面散伙。❗ 传统概念验证沦为坟墓，因为它"无限期、无指标、无裁判"。
- [ ] **防线二：警惕三类高危信号**（出现两个以上高度警惕）：
  - ❗ 没有业务负责人（只有信息部门对接）——信息部门关心合规与稳定，而从不是做新项目的理由。
  - ❗ 只许看不给碰（拒绝提供真实数据）——注定做出自欺欺人的假阳性。
  - ❗ 宇宙级需求（第一次会议就要"覆盖全公司所有场景"）——往往还没准备好做任何一个场景。
- [ ] **防线三：给拒绝留体面台阶**。把"现在不做"翻译成"什么时候做"："数据基础还差 3 件事，先做另一个场景顺手补齐，下季度再来。"

### 1.3 MVD 三军规（最小可行部署）

> 对应 MVP，但裁判是"这个具体客户的具体业务"。价值不能继承，只能逐个验证。

- [ ] **军规一：真实数据，没有例外**。❗ 用脱敏样例数据或自构演示数据做验证 = 概念验证坟墓的第一块砖。真实数据里藏着一切魔鬼：字段含义与文档不符、三成空值、三年前编码规则、数据本身记录着错误的流程。
- [ ] **军规二：缩小切口，不缩小野心**。不砍价值、砍范围。追求"只覆盖退换货这一类工单，但端到端无人干预"，而非"覆盖全公司智能客服"。切口小到价值密度肉眼可见、业务部门主动传播。
- [ ] **军规三：定死截止时间，倒逼取舍**。参考标准：MVD 验证周期以**周**计（2-6 周），不是月。Palantir 训练营 1-5 天，Sierra 最快 4 周，Decagon 4-8 周。❗ 一个 6 个月的"最小验证"几乎必然重新长成什么都想要的大项目。

### 1.4 "读旧写新"原则（早期迁就客户环境的中间路线）

- [ ] **数据层：深度兼容旧系统**。客户数据在哪就从哪读——哪怕在老式主机、共享盘表格、古老系统私有接口里。数据是验证价值的前提，它不会为迁就你的架构而搬家。
- [ ] **架构层：绝不寄生旧系统**。验证期方案运行在自己可控边界内，通过接口与旧系统交互。理由：①验证期方案过半概率被推翻重写，寄生越深浪费越大；②写入旧系统要走变更管理流程，周期以月计，与 MVD 周级节奏冲突；③保持"可撤离"姿态是谈判筹码和诚实姿态。
- [ ] **流程层：顺从人的习惯，不是系统的习惯**。❗ 如果业务用户核心动作在表格和邮件里，MVD 界面就应出现在表格插件和邮件里。新系统最大的敌人不是旧系统，是旧习惯。

### 1.5 影子工作法（找到真痛点）

> 痛不会出现在会议室里，只会出现在工作现场。源自人类学"参与式观察"和丰田"现地现物"。

- [ ] 跟着真实用户过完他真实的一天——不是采访，是坐在旁边看他工作。
- [ ] 看他打开哪些系统、在哪些表格间复制粘贴、在哪些环节皱眉、绕过哪些"官方流程"。
- [ ] **重点观察"变通"而非"流程"**。每个变通 = 一个未被满足的痛点在尖叫。员工为什么坚持导出到表格再算一遍？为什么"这张表要找小王"？
- [ ] **警惕"翻译过的痛点"**。经信息部门/采购/顾问转述的需求每手失真一次。绕过翻译件，直达疼痛的神经末梢。
- [ ] 找到"知道流程为什么是那样的人"——这三样（没人写进文档的工作流、真正信任的数据源、知道流程为什么是那样的人）每一样只能在现场找到。

### Phase 1 关键产出物

- [ ] PSF 三关检验报告（含量化靶子）
- [ ] 毕业标准（周期上限 + 验收指标 + 达标/散伙两种后续）
- [ ] MVD 方案（真实数据源 + 单一切口 + 周级死线）
- [ ] "读旧写新"的架构决策
- [ ] 影子工作法田野笔记（含变通清单、真信任数据源、关键人）

## Phase 2 ｜ 赢得客户（第 3 章）

> **核心信条**：赢得客户的本质，是在一个被辜负过无数次的市场里，成为值得被信任的那个例外。
> 签下合同只是入场券——真正的硬仗在后面。

### 2.1 灯塔客户筛选

- [ ] **战略价值三检验**：
  - 销售资产价值（同行背书 = 最短说服路径）
  - 产品基因塑造（前 10 个客户事实上在塑造你的产品，选错会被带向没有普遍性的方向）
  - 学习价值（每次交付的学习能否累积而非互相抵消）
- [ ] ❗ 接错灯塔的代价不是"少赚一单"，是一支顶尖团队被泥潭占用半年。质量比数量重要一个数量级。
- [ ] **灯塔特有检验**：合作初期就谈好，成功后他愿不愿意站出来——联合发案例、行业会议现身说法、接待参访。不愿公开替你说话的灯塔，价值至少打对折。

### 2.2 警惕"需求蝗虫"（三个识别特征）

- [ ] ❗ 需求与公司战略方向明显偏离，做了也沉淀不下可复用能力。
- [ ] ❗ 把 FDE 当廉价外包使唤，按人头派活而非按结果对齐。
- [ ] ❗ 内部政治消耗巨大，你的主要工作变成帮某部门证明另一部门错了。

### 2.3 排期三原则（谁先谁后本身就是战略）

- [ ] **原则一：按战略价值排，不按合同金额排**。决策矩阵两维度：灯塔价值（行业信号强度）× 学习价值（可复用能力）。两高客户可倒贴资源优先做；两低大合同最危险——钱多但套牢精英团队半年。
- [ ] **原则二：把"等待"产品化**。给排队客户：数据准备清单（进场即提速）、组织预热建议、轻量远程诊断（保持温度、提前扫雷）。经营得好进场后交付周期缩短 1/3。
- [ ] **原则三：永不承诺超越产能的并行**。一支合格小分队（1 业务 + 2-3 技术）同期高质量交付不超过 2 个项目。宁可把"档期排到下季度"当稀缺性卖（往往能提价）。

### 2.4 进场尽调五份地图（写第一行代码之前，1-2 周）

- [ ] **数据地图**：有哪些数据源、谁拥有、质量如何、权限归谁、有没有暗数据（私藏表格、邮件报表、纸质台账）。重点不是"有什么"是"哪个被信任"。
- [ ] **流程地图**：真实运转图（影子工作法观察版，非流程文件版）。标注三个点位：时间消耗最大、出错代价最大、情绪最激烈 = 价值富矿。
- [ ] **组织地图**：谁发起、谁买单、谁使用、谁能否决、谁是无冕之王。特别找"知识枢纽"（职位不高但所有人遇问题都找他）= 最好的需求源 + 日后推广种子。
- [ ] **系统地图**：对接系统清单及接口状态、安全合规边界、变更管理流程。❗ 很多项目时间表第一天就注定破产，因为没人问"客户发一个版本要走 6 周流程"。
- [ ] **政治地图**：动了谁的奶酪？自动化目标流程是不是某部门的权力来源？❗ 员工抵触的根源不是懒，是恐惧——怕被取代、怕被证明无能。提前识别恐惧载体，给他们安排"新生路"而非"死路"。

### 2.5 通关三闸门（采购 / 法务 / 安全）

> 把它们当阻碍，会在最后一公里翻车；把它们当交付的一部分，反而能建立优势。

- [ ] **采购关**：给"可交差"的工具——清晰分阶段报价（让降价有台阶）、可对比市场基准（让审批有依据）、可衡量结果承诺（让"买贵了"指控无成立）。成果计价有优势："每解决一工单付 X 元"采购一眼看懂。
- [ ] **法务关**：把数据处理协议当产品打磨。预置协议模板、清晰模型使用声明、分级事故责任框架。❗ 法务信任是设计出来的，不是谈判出来的。
- [ ] **安全审查关**：用"预答白皮书"抢两个月。维护：部署架构图、数据流图、加密权限方案、合规认证、历史被问问题标准答案。多数问卷 8 成可复制粘贴。响应速度本身 = 安全成熟度信号。

### 2.6 提案倒金字塔（企业市场单价最高的文本）

- [ ] **第一层：业务结果**，一段话说完。客户语言，如"8 周内把反洗钱调查平均处理时间从 4 小时降到 15 分钟，释放产能相当于现有团队 2.5 倍"。❗ 没这一句，高管根本看不进后面。
- [ ] **第二层：价值验证路径**。验收指标、测量方法、基线数据、每阶段退出机制。信号 = "我们敢被检验"。
- [ ] **第三层：交付方法**。技术方案但非技术读者能跟上，里程碑配决策点。特别写明需要客户配合的事项（数据访问、关键人员投入时间）——提前排雷 + 筛选客户。
- [ ] **第四层：风险与对策**。❗ 多数提案回避风险仿佛不吉利。成熟买家最信任"把死法说清楚"的供应商：数据质量不达标怎么办、关键人员变动怎么办、准确率达不到门槛怎么办。

### 2.7 混合交付边界（从驻场到远程）

- [ ] **必须物理在场的三类时刻**：关系建立初期、高强度共创（训练营式联合构建）、政治敏感期（方案推广/变革管理）。信任隔着屏幕建不起来。
- [ ] **远程反而更好的**：深度编码、文档沉淀、常规迭代（需要无打扰心流）。
- [ ] ❗ 底线：从不见面的 FDE 是伪命题。远程维持的是已有的信任与语境，而它们必须先在物理世界被创造。

### Phase 2 关键产出物

- [ ] 灯塔客户矩阵（战略价值 × 学习价值）
- [ ] 排期决策（含等待期经营方案）
- [ ] 进场尽调五地图
- [ ] 安全/法务/采购白皮书与模板
- [ ] 倒金字塔提案 + 概念验证方案（含毕业标准）

## Phase 3 ｜ 激活部署（第 4 章）

> **核心信条**：企业软件的"上线"是行政事件，"激活"是行为事件。前者可以庆祝，后者才算数。
> 系统上线不是里程碑，客户团队改变工作方式才是。

### 3.1 激活三道关（和消费产品完全不同）

- [ ] **不顺手关**：比旧习惯多一步就没人用。
- [ ] **不可信关**：错一次，信任清零。
- [ ] **与我无关关**：那就更没人碰。
- [ ] ❗ 没有一关能在总部解决，只能到客户会议室、车间、工位上过。

### 3.2 武器一：热修复文化（部署期迭代以天/小时计）

- [ ] 反馈直达写代码的人，中间不隔着传话筒。最好写代码的人就坐在用户旁边。
- [ ] 迭代优先级按"使用阻塞度"排序，不按"功能重要度"。一个配色让车间工人觉得"这是给白领做的"= 最高优先级。
- [ ] 每天收工问：今天的改动让用户明天哪一刻更顺了？
- [ ] 交付阶段仍以"多日驻场"为单元——能修这么快，靠的是人守在问题旁边。

### 3.3 武器二：评估体系（AI 时代 FDE 标志性技能，2024 年后才主流）

> 没有"好"的标尺，AI 部署迭代就是蒙眼狂奔——你以为在优化，其实在随机漂移。

- [ ] **第一步：从真实案例长出来**。评估集不能靠工程师编，必须来自客户真实业务语料。本质 = 把业务专家隐性判断力显性化为可执行标尺。
- [ ] **第二步：让业务方当评委**。并排输出对比、简单优劣标注、定期评审会。双重收益：评估集越来越准 + 业务方对系统理解越来越深（看着自家案例一次比一次答得好）。
- [ ] **第三步：接到生产回路**。上线不是评估终点。持续采集真实输入输出，定期抽样评估，分数下滑立即告警。用户最敏感的不是平均质量，是稳定性——错一次的信任塌方需要十次正确填回来。
- [ ] 参考 John Deere 样板：先和农艺专家评审数百真实案例建定制评估体系，再迭代模型。最终化学品减 70%、互动提升 6 倍。**先有评估体系定义的"好"，才有模型交出的"好"**。

### 3.4 武器三：降低使用门槛四手法

- [ ] **寄生在用户已有界面里**。他在表格工作就做表格插件；邮件审批就在邮件完成；工单系统就把 AI 建议嵌进工单卡片。❗ 每多一次登录，激活率流失一截。
- [ ] **默认值里藏着激活率**。新用户面对空白系统第一反应是"然后呢"，多数流失在这 3 秒。把"第一次使用"预装好：预置模板、预填示例（基于客户自己的数据）、预设引导。
- [ ] **把"问 AI"翻译成"点按钮"**。把高频场景封装成一键动作："生成上周异常报告""核对这批发票"。对话式留给探索，按钮式留给日常。
- [ ] **先副驾驶，再自动驾驶**。高风险高抵触流程让系统先以"建议者"存在——AI 起草人来确认，用户在一次次确认中建立信任校准。John Deer 至今保留农艺师最终决策权。

### 3.5 武器四：集成大战四要点（每个 FDE 老兵的伤疤）

- [ ] **把集成当战役打，不当杂务办**。❗ 计划里写"系统对接 2 周"然后膨胀成 4 个月是常态。进场尽调就画系统地图，集成风险分级排期，最硬的骨头最早啃。
- [ ] **数据问题先于模型问题解决**。❗ "垃圾进垃圾出"——AI 接入未治理数据源，同文档十个版本随机命中，输出自然不可信。数据治理不是 AI 项目前置工程，它就是 AI 项目本身。
- [ ] **用 AI 打 AI 的集成战争**。没有接口的老系统用浏览器智能体模拟人取数；字段映射、格式转换、接口文档解读交给模型。尽最大可能自动化集成流程——速度优势会复利。
- [ ] **知道何时绕开而非攻克**。有些系统用"影子读取"（只读快照/夜间同步），有些"人工摆渡"（过渡期保留人工），有些干脆"宣告隔离"（明确告知不在范围）。判断力体现在选择战场——目标不是技术全胜，是客户结果。

### 3.6 武器五：变革管理三组人物

- [ ] **支持者（内部盟友）**：给他能讲的材料、给他战功、给他安全感（失败时你顶前面）。一个被善待的支持者胜过十场宣讲会。
- [ ] **影响者（非正式意见领袖）**：请他们第一批试用、认真对待每条吐槽、把采纳他们建议显性化（"这字段按王师傅意见加的"）。他们一句"还真行"抵三封全员邮件；一句"花架子"足以让系统基层无声死亡。
- [ ] **受损者（利益群体）**：❗ 忽视他们，他们会成最顽强的地下抵抗者——消极不配合、传播事故、验收投反对票。把被释放人力导向更高价值工作（公开承诺不裁员）、把"守门人"转型为"教练"（老师傅经验用来训练系统）。
- [ ] **终极检验**：团队撤场后系统是否依然被使用。在场热火朝天、撤场迅速冷却 = 伴舞不是激活。

### 3.7 武器六：交付工作本身的自动化（摆脱收入随人头线性增长的第一杠杆）

- [ ] 每一个第二次做的动作，触发提问："这能变脚本/模板/清单吗？"
- [ ] **部署模板**：环境搭建、权限配置、监控接入打包成一键式基础设施代码。新客户第一天拉起标准化环境。
- [ ] **集成组件库**：主流企业系统连接器，写一次处处复用。
- [ ] **检查清单文化**：安全审查清单、上线准入清单、撤场交接清单。把"依赖个人经验"变成"依赖组织记忆"。
- [ ] **自动化汇报**：向客户的周报、向公司的现场情报应半自动生成。

### Phase 3 关键产出物

- [ ] 评估体系（真实案例集 + 业务方评审流程 + 生产回路）
- [ ] 热修复迭代日志（含使用阻塞度排序）
- [ ] 集成风险分级排期表
- [ ] 变革管理三组人物地图（支持者/影响者/受损者及其出路）
- [ ] 部署模板 + 组件库 + 检查清单 v1

## Phase 4 ｜ 守住续约（第 5 章）

> **核心信条**：续约率是 FDE 商业模式的生死线。获客成本动辄数十万美元，续约成本趋近于零。
> 只守不攻的企业关系会萎缩——但先得守住。

### 4.1 防五类流失死因（按可预防性排序）

- [ ] **价值蒸发**：系统还在跑但没人记得它解决了什么。对策 = 持续向组织（尤其新任管理者）重述"我们为什么有这套系统"。价值不是一次性证明的，是需要不断重新证明的。
- [ ] **支持者离场**：升职/调岗/离职，继任者无感甚至敌视"前任政绩"。行业黑话："支持者一动，合同就悬。"
- [ ] **质量漂移**：业务/数据/模型在变，输出质量缓慢下滑，信任缓慢塌方。
- [ ] **成本反噬**：用量越大账单越高，价值叙事跟不上时"成功"反成续约障碍。
- [ ] **供应商戒断反应**：客户对"被绑定"的警惕。❗ Gartner 预测 2028 年 70% 企业将因供应商成本过高与内部技能不足，被迫放弃 FDE 主导方案。这个预测是对所有 FDE 的警告。

### 4.2 守住可靠性的四道工事

- [ ] **明确服务承诺并让它可见**。可用性/延迟/错误率承诺做成客户自己能看的监控面板。把"系统很稳"从需辩白的立场变成可查事实。
- [ ] **为 AI"概率性"设计护栏**。拿不准的输出标注或转人工；高风险动作有人把关；模型每次大更新重新过评估。护栏样板：Anthropic 把"可审计、可追溯"作为核心设计，每个决策能回放证据链。在金融/医疗，可审计性不是加分项是准入证。
- [ ] **值班响应让客户感到你一直在**。凌晨两点系统挂了，FDE 反应速度 = 客户对关系的体感温度。值班轮换、事故复盘、每次事故后诚实通报。企业客户能接受事故，不能接受隐瞒。
- [ ] **容量与成本同步规划**。永远跑在用量曲线前面半步：旺季来临前容量/限流/降级预案就位。客户还没感觉到慢就把慢消灭掉。

### 4.3 有损服务——克制的艺术（定制化 vs 标准化永恒撕扯）

- [ ] **功能维：敢对长尾需求说"不做"**。判断标准两问：它服务的用户数 × 频率，值不值终身维护成本？它能否泛化为平台能力（值则进回流通道）？两答否则给变通方案而非代码。❗ FDE 不是接单员。
- [ ] **承诺维：分级承诺不一律最高**。核心交易链路按最高标准守护，报表与探索性功能大方接受降级。降级策略（高峰关重计算）、错峰策略（重任务夜里跑）、事先言明的分级承诺。
- [ ] **成本维：用量账单主动管理**。❗ 在客户财务负责人问起之前先把"账单对应的价值账"算给对方看。等你被叫去解释账单，已输一半；主动算清的人，续约谈判时手里全是牌。

### 4.4 新用户引导（永不结束的滚动过程）

- [ ] **分层培训**：管理员/内部支持者深度培训；普通用户场景化培训（"你日常三件事怎么用系统做"，30 分钟封顶）；高管一句话培训（"打开这里，这个数字就是答案"）。
- [ ] **"培训培训师"杠杆**：识别客户组织热情分子，培养成内部讲师——官方认证、专属支持通道、高管面前曝光。教会客户教自己 = 交付最高形态。❗ 厂商培训的从来不是"用户"，而是"会去培训别人的人"。
- [ ] **文档与自助体系**：以任务而非功能组织（"如何处理异常退款"而非"退款模块功能说明"），嵌入产品而非独立存在（在用户卡住处就地出现）。

### 4.5 组织维系防单点依赖

- [ ] **关系网格化**：一个支持者之外，至少再发展两条独立关系线——业务线日常使用者社群（内部讲师是天然节点）+ 更高一层高管赞助人。检验标准：任何单个人离开，信息通道都不中断。
- [ ] **价值组织化**：把系统价值从"支持者政绩"改写为"组织资产"。价值数据定期全员通报、成功案例在内部会议反复讲述、把系统嵌入流程文件（写进标准作业流程 = 最强制度性锁定，替换它需改写流程）。
- [ ] **离场做成仪式**：为离开的支持者办"功成"仪式（感谢信、成就总结、赠职业资本如对外分享案例资格），第一时间启动与继任者交接——以"帮继任者快速出成绩"为切入点，而非"说服他保留我们系统"。❗ 善待离场者 = 把流失风险转化为获客通道（他去了新东家就是你下一个客户的潜在入口）。

### 4.6 健康度与唤醒机制

- [ ] **四类信号合成健康分**：使用信号（周活人数趋势、关键功能几成人在用、真用还是打卡）、价值信号（业务指标现状、投资回报故事是否成立）、关系信号（支持者在职状态、近 30 天高层接触次数、客户对你团队响应速度）、商业信号（用量与账单比率趋势、合同到期时间、竞品动向）。
- [ ] **跌破警戒线分级响应**：
  - 轻度下滑（某部门使用减少）→ 内部讲师上门回访
  - 中度下滑（整体活跃降三成）→ FDE 团队专项诊断（通常业务变化/人员变动/质量漂移三者之一，对症处置）
  - 重度下滑（濒临停用）→ 高管层介入，坦诚对话"还值不值得继续"，有时答案是体面退出/降级，保住关系与口碑
- [ ] **季度业务回顾（QBR）三纪律**：讲客户语言非产品语言；让客户业务方当主角非听众；以"下季度价值计划"收尾。续约不该是到期前一次谈判，应是每季度自然续写的连续剧。

### Phase 4 关键产出物

- [ ] 五类流失风险登记表（每客户）
- [ ] 可靠性四工事（含监控面板、护栏、值班、容量预案）
- [ ] 分级承诺与用量账单主动管理方案
- [ ] 分层培训体系 + 内部讲师认证计划
- [ ] 关系网格图 + 健康度仪表盘 + QBR 模板

## Phase 5 ｜ 扩大收入（第 6 章）

> **核心信条**：FDE 模式的收入不是销售的战利品，而是价值的影子。你创造的价值越大，影子越长。
> 最大的收入增长不在新客户，在老客户内部。

### 5.1 免费→付费的五个开关（验证转付费是事故最高发环节）

- [ ] **开关一：毕业标准先于开工**。周期上限、验收指标、达标后进入商务谈判的约定白纸黑字。Palantir 训练营日程表上"演示"后紧跟"拍板"——转化不是事后事件，是日程表上的一格。
- [ ] **开关二：免费边界显性化**。❗ 客户必须清楚知道免费到哪天、覆盖什么、超出如何计价。模糊边界培养"免费是常态"预期，收费时客户感觉是"被宰一刀"。
- [ ] **开关三：让内部支持者成为销售员**。武装他：一页纸价值报告（数字/对比/同事证言）、应对财务质询的问答集、"如果不继续"的机会成本陈述。内部人推销的内部信任度，外部人够不着。
- [ ] **开关四：价格锚点提前埋设**。免费期就开始谈价值——"这套系统这个月为你们释放了约 120 个人时"。免费期只谈功能不谈价值 = 报价单是突兀惊吓。
- [ ] **开关五：给"不转正"设计体面出口**。保留数据与配置、约定重启条件、维持轻量联系。企业市场很小，今天"明年再说"常是后年的大单。

### 5.2 成果计价四档进化链（越往上越贴近价值也越难执行）

- [ ] **按用量**：按模型计量/调用量/处理量。清晰可测但追踪的是成本非价值。
- [ ] **按行为**：按"完成一次退货处理""生成一份合规报告"。计价单位开始有业务含义。
- [ ] **按结果**：按"成功解决的会话""追回的一笔坏账"。Sierra 标杆。执行难点在归因——"解决"的认定需双方认可的判定标准（这正是评估体系的商业用途：技术评估体系同时是计费基础设施）。
- [ ] **按价值分成**：按创造的财务价值提成——省下成本、追回收入、释放产能。最贴近价值的终极形态，最难：需客户开放财务数据、抗周期信任、极强价值测量能力。
- [ ] **判断原则**：计价单位越贴近客户价值，定价天花板越高，但测量与信任成本也越高。
- [ ] **中国市场注脚**：纯订阅制是理想，混合制是活路——按阶段交付验收（顺应项目制习惯）+ 价值指标写入验收标准（注入成果计价基因）+ 年度运维演进合同（培育续约意识）。

### 5.3 存量深耕三方向（登陆与扩张）

- [ ] **横向（团队→邻接团队）**：帮客服做成智能工单，隔壁售后/技术支持就是下一个最容易拿下的客户。同公司同数据环境同事现身说法，几乎不需重建信任。
- [ ] **纵向（执行层→决策层）**：把价值链往上传导——为中层做分析预警，为高管做决策驾驶舱。❗ 只被基层喜爱的系统在预算季没有辩护者；进入高管视野才进"固定资产"行列。
- [ ] **纵深（辅助工具→核心流程）**：从"给建议"到"执行业务动作"，从"可选"到"标准作业流程一部分"。每步伴随更大责任与更高信任门槛，但构建最深护城河——替换工具只要换软件，替换嵌入流程的系统等于做手术。
- [ ] **节奏纪律**：扩张必须由价值牵引而非销售指标牵引。健康度体系有进攻性用途：使用深度高、价值明确的部门就是扩张下一目标；客户"看到别人用得好、主动来问"的时刻 = 黄金窗口（你在响应需求不是推销）。

### 5.4 变惩为奖：用量与扩容定价心理学

- [ ] ❗ 禁用"惩罚式超量"——超额按高价计费或限流降速。这惩罚的正是你最想要的：深度使用。客户压抑使用→价值缩水→续约双输。
- [ ] **手法一：阶梯价格越用越便宜**。把"超量焦虑"转成"冲量动力"。合同里表达清楚：客户看到的是"用多了单价更低、更划算"。
- [ ] **手法二：超量预警 + 主动升舱**。监测到将超量时主动上门："照这趋势升一档套餐省 15%"。把计费事件转成顾问式销售机会。隐含收益：逼团队持续关注客户用量健康度。
- [ ] **手法三：把"省下来"的功劳还给客户**。用量优化（模型分层/缓存/批处理）降本，主动算给客户听："这季度架构优化为你们省了 X 万。"在财务负责人眼里，主动帮省钱 vs 等着客户超量 = 两种物种。
- [ ] **底层道理**：计价结构每天向客户讲述"我们什么样的关系"。惩罚式讲"我们盯着你"，奖励式讲"我们一起长大"。

### 5.5 价值度量系统（贯穿所有客户交付的基础设施工程）

> 前几章的东西在这里会师：第 2 章经济性检验是输入，第 4 章评估体系是微观基础，第 5 章健康度是运营界面，本章计价扩容是商业出口。

- [ ] **对客户**：续约与扩容的证据库。被数据武装的续约谈判 vs 凭感觉的续约谈判，成交率不在一个量级。
- [ ] **对公司**：交付质量体检仪。哪类场景价值密度最高（销售火力引向哪）？哪类客户交付成本最高（定价/打法要调整）？哪些部署在创造价值、哪些在空转（资源重新配置）？
- [ ] **对产品**：回流情报放大器。哪个功能价值产出最高（加大投入）？哪个无人使用（果断下掉）？哪个场景反复被定制（平台化信号）？
- [ ] **对市场**：信任营销素材库。"化学品减 70%""调查从数小时到数分钟"——让行业记住的数字全部来自这套系统的积累。
- [ ] **三条实践建议**：①从第一天采集基线（错过永不再来）；②指标必须与客户共建（他不认的指标算出花来也无谈判效力）；③克制数量（每客户 3-5 个核心指标足矣，一多等于没有）。

### Phase 5 关键产出物

- [ ] 免费→付费转换五开关设计
- [ ] 计价档位选择 + 中国混合制方案
- [ ] 存量深耕三方向扩张地图
- [ ] 阶梯定价 + 超量预警机制
- [ ] 价值度量系统（基线采集 + 共建指标 + 四类出口）

## Phase 6 ｜ 规模化复制（第 7 章）

> **核心信条**：每做完一个客户，下一个就该更好做——靠的不是加人，而是把上一次的经验攒下来。
> 抽掉本章，前面六章的结局 = 一支精英团队接一个、交付一个、覆盖成本、再接下一个，收入与人数完全线性。恭喜，你重新发明了咨询公司。

### 6.1 三级复制杠杆（一级比一级难，一级比一级值钱）

- [ ] **一级杠杆｜知识复制（打法手册）**：把"怎么做"写成文档。新人上手周期从 1 年压到 3 个月。多数团队止步于此。
- [ ] **二级杠杆｜组件复制（工具与代码）**：把"做过的"变成"能直接用的"——集成连接器、评估框架、部署模板、行业数据模型。下一支团队起点不再是零。
- [ ] **三级杠杆｜产品复制（平台能力）**：把"反复出现的定制"抽象为平台标准能力——从此此需求不再需要任何工程师到场。❗ 前两级降低交付成本，第三级消灭交付成本。

### 6.2 失败复盘三机制（失败是复制的原材料，掩盖失败 = 把金矿当垃圾埋掉）

- [ ] **无罪化**：复盘唯一规则是对事不对人。一旦与绩效挂钩，人们开始修饰失败，修饰过的失败毫无教学价值。"责"重新定义为"是否诚实完整提取了教训"。诚实复盘的失败项目负责人，对组织贡献可能大于侥幸成功的。
- [ ] **结构化**：复盘产出必须是可检索可执行的知识——这个客户类型高危信号？哪个集成假设被推翻？哪个评估指标设计错？结论进入打法手册"雷区"章节、进入新项目尽调清单。❗ 失败只有写进流程才算真正被吸取。
- [ ] **适度外传**：脱敏后对外分享 = 极高效信任营销。读者能分辨谁讲展台话术谁讲战壕真相。敢于公开解剖失败的团队传递的信号 = "我们已经为这行业弯路付过学费"——正是企业客户最想听到的。

### 6.3 打法手册三属性（多数手册写成"写完即死"的文档坟场）

- [ ] **属性一：长在流程里，不是躺在知识库里**。只能在文档系统被搜到的手册 = 不存在。嵌入工作流：尽调阶段系统自动弹出该客户类型尽调清单；部署阶段检查清单是任务系统硬关卡；复盘阶段手册更新是必填产出。❗ 知识不嵌入流程就只是考古资料。
- [ ] **属性二：按"场景"非"功能"组织**。失败手册按组织结构写（"交付流程""技术规范"），成功手册按客户场景写（"金融反洗钱场景打法""制造业排产场景打法""律所知识库场景打法"）。每场景固定七件套：①典型痛点与契合检验要点 ②尽调清单（场景特有高危信号）③数据与集成已知雷区 ④评估与验收指标模板 ⑤变革管理角色地图 ⑥计价与扩容参考结构 ⑦历史复盘教训库。
- [ ] **属性三：必须"活"——有负责人、有版本、有折旧**。每场景手册指定负责人（通常最资深那支交付团队），每项目结束强制回看更新，每半年整体检修——删过时、合并重复。❗ 没负责人的手册一年内腐烂成误导新人的陷阱，比没手册更糟。

### 6.4 产品化四问（现场经验结晶为产品的炼金术）

- [ ] **第一问：是"个性"还是"共性"？** 同类问题是否在 3+ 客户那里独立出现过？3 个客户的相同痛点是产品信号，1 个客户的特殊要求可能只是怪癖。让"多支团队的重复造轮子"自然暴露共性。
- [ ] **第二问：泛化代价是否小于收益？** 现场代码"快而糙"，泛化成本"往往高于写第一版"。算账：泛化投入 vs 未来若干客户省下的定制成本。算不过来留在组件层，不强行平台化——平台里每个能力都是终身维护承诺。
- [ ] **第三问：能否被"不会写代码的人"使用？** 产品化最难一步往往不是技术是交互：把工程师脚本变成业务人员能配置的功能。抽象层选对，能力用户群扩大百倍。
- [ ] **第四问：收编之后现场还有空间吗？** ❗ 最微妙平衡：平台收编太多→现场退化为配置员，FDE 灵魂（现场创造力）死了；收编太少→规模化杠杆起不来。解法：保持"前线对基地的激进授权"——高层只定目标，打法归现场。平台负责让"常见的事容易"，现场负责让"不可能的事发生"。

### 6.5 规模化中的组织政治三心法（最大障碍从来不是技术，是人的地盘）

- [ ] **心法一：扩张必须带"当地人"**。每进一个新部门先找"地头蛇"（最有声望的资深员工），邀请参与适配："这场景你们部门有什么不一样？"❗ 人们不会反对自己参与建造的东西。
- [ ] **心法二：让每步扩张都有"受益者"**。扩张前算清每个相关部门得到什么：被穿透数据壁垒的部门得到全局可见的分析能力；被压缩审批权的部门得到例外事项聚焦权。没有受益者的扩张是侵略，有受益者的扩张是解放。
- [ ] **心法三：给"旧秩序"留体面**。被替代的流程曾是某能干的人设计的；被编码的经验曾是某专家的毕生心血。话术里尊重旧秩序 = 尊重其维护者："这套流程过去十年支撑了公司，现在我们要把它十年经验放大一百倍。"

### 6.6 传播循环与产品内置裂变

- [ ] **三个圈层飞轮**：从业者社区（为共同体贡献内容，名字与新兴职业绑定）→ 客户行业社区（让客户支持者在他行业峰会上替你讲十分钟，胜过展位一百天）→ 生态伙伴网络（让云厂商/咨询/集成商在你合作中"赢"，帮别人成功的人被整个网络记住）。
- [ ] **可见性设计**：输出物携带"出身"——报表页脚"由某某系统生成"、预警里处理入口链接。价值在工作流中自我展览而非靠专门汇报。
- [ ] **协作式准入**：设计需跨角色协作的功能（调查官标注→主管复核），每个协作动作向新用户自然介绍系统。
- [ ] **自助化探索层**：核心交付外留低风险练习区（沙盒），让客户员工自己玩出场景。❗ 让全民帮你做发现，让 FDE 做攻坚。Sierra "代笔人"/Decagon 智能体操作流程 = 让客户自助造 Agent，FDE 从"每个都亲手做"变"验收和兜底"。
- [ ] **跨边界价值证据**：每季度自动生成"本季度价值报告"自然流向高管层。既是续约工程也是纵向扩张敲门砖。

## 度量层 ｜ FDE 全流程指标体系（附录 A）

> 指标贵精不贵多——每个项目盯住 3-5 个核心指标组合（通常 1 个价值指标 + 1 个使用指标 + 1 个关系指标），胜过铺满一面墙的仪表盘。

### 交付层（项目做得对不对）

- [ ] **TTV（价值实现时间）**：进场到客户获第一次可衡量价值的时间。参考标准：MVD 验证以周计（2-6 周），完整部署以月计（1-4 个月）。❗ TTV 持续变长 = 方法论或平台底座出问题的第一信号。
- [ ] **概念验证转化率**：参考 Palantir 训练营从早期 5-10% 提升到约 75%。过低 = 进场筛选失职；过高（接近 100%）= 检查是否只接没挑战的单。
- [ ] **评估达标率**：AI 输出通过业务评估集的比例 + 生产环境时间序列走势。质量漂移报警器。
- [ ] **部署频次与回滚率**：部署期应保持高频小步（周级甚至日级），回滚率低而稳定。
- [ ] **缺陷逃逸率**：上线后才被发现的缺陷占比。测的是测试与评估体系完备性，非工程师水平。

### 客户层（客户活得怎么样）

- [ ] **激活率**：目标用户群中形成稳定使用习惯的比例。❗ 分母是"目标用户群"非"系统账号数"。MIT 报告警戒线：仅约 4 成企业提供官方 AI 工具订阅。
- [ ] **使用深度**：关键功能几成人在用、使用频次分布（打卡式 vs 工作流嵌入）、自助探索行为出现（最珍贵信号）。
- [ ] **健康度评分**：使用/价值/关系/商业四类信号合成。纪律：每周全量巡视，跌破警戒线自动触发干预。
- [ ] **支持者覆盖数**：单点高危，三点成网。
- [ ] ❗ **NPS 慎用**：企业场景样本小、政治化。更可靠替代 = "续约意向提前问询"（到期前两季度直接问支持者"如果今天续约你会续吗"）。

### 商业层（生意值不值）

- [ ] **NRR（净收入留存）**：FDE 商业模式总裁判。及格 100%，优秀 120%。>120% 增长引擎已内生。参考 Palantir 139%。
- [ ] **交付毛利率**：及格线随平台化程度浮动——纯人力期 20-40%，平台复用上来后应向 60%+ 上升。❗ 毛利率涨得快不快比绝对值高低更能说明模式成不成——不上升的 FDE 是咨询公司。
- [ ] **定制递减率**：麦格鲁试金石——第 N 个客户定制量应显著小于第 1 个。连续三个不降立即检视产品回流机制。
- [ ] **销售周期**：参考 Palantir 用训练营从 9-12 个月压到数周。获客效率与信任资产厚度综合读数。
- [ ] **CAC 回收期**：含免费验证投入。前期普遍难看，关键看随案例积累而缩短的趋势。
- [ ] **LTV/CAC**：健康线一般 3+。FDE 早期可能低于 2，必须配合 NRR 一起读才有意义。

### 组织层（团队能不能走远）

- [ ] **现场到产品回流速率**：单位时间内从现场沉淀为组件/平台能力的产出数（组件入库数、手册更新数、平台化提案数）。❗ 测的是 FDE 模式"灵魂器官"是否还在跳动。
- [ ] **交付资产复用率**：新项目中复用已有组件/模板/清单的比例。三级复制杠杆综合读数，目标逐季上升。
- [ ] **FDE 人均产能**：每名 FDE 支撑的年收入。纯人力模式天花板明显，平台化后应持续抬升。
- [ ] **团队续航指标**：月出差天数、值班负荷、离职率与倦怠预警。❗ Reddit 上 FDE 最大吐槽点 = 差旅与续航——团队烧干了，前面所有指标都是烟花。

## 道德底线 ｜ FDE 的六条职业操守（后记）

> FDE 手里握着的不是一般的技术——是客户组织最深处的秘密，和越来越大的代替人做决定的权力。
> 能力越大的部署者，越需要把边界写在方法之前。

- [ ] **一、数据主权属于客户**。现场看到的数据一个字节都不出现在不该出现的地方——不进训练数据（除非合同授权）、不进案例素材（除非书面同意）、不进下一份工作的谈资。最小知情原则：能不看就不看，能脱敏就脱敏。
- [ ] **二、诚实报告结果，包括坏消息**。❗ 按结果收费的模式里最大道德风险 = 粉饰结果。把"系统上线了"包装成"价值实现了"，把相关性包装成因果。价值度量系统既可是最诚实工具也可是最精巧谎言机器，区别只在人心。
- [ ] **三、不制造依赖，不贩卖恐惧**。不故意把系统做成黑箱让客户离不开你；不夸大"不用 AI 就会死"的恐慌促成交易。健康的 FDE 模式是"做完会走"——知识转移给客户，能力沉淀给客户团队。❗ 让客户强大，而不是让客户上瘾。
- [ ] **四、把"被替代的人"当回事**。不在被替代者面前庆祝效率，不在方案里把人写成"成本项"而不给出路，不对自己"正在改变谁的命运"装糊涂。技术的中立是神话，部署者的选择是现实。
- [ ] **五、对"客户要求但不该做的事"说不**。游走合规边缘的要求（"把员工行为监控做得再细点""这数据合规模糊但先接了再说"），"法国侍者"在此有最深含义——真正专业不是满足一切要求，是敢于引导客户走向对他真正有利、对世界无害的方向。说不的底气来自账上有别的客户；道德从来也和商业模式有关。
- [ ] **六、记住你代表的是"技术"本身**。对很多客户你是他们接触 AI 的第一张人脸。你的每次夸大透支整个行业信用；每次兑现为整个行业存款。部署者是技术与人类日常之间最后一道翻译——翻译失真的代价，由所有人支付。

### 一个 FDE 项目开工前必须有的 5 样东西
1. PSF 三关全过（痛点 + 经济性 + 可行性）

按结果验收｜带平台底座｜做完会走能力留下

### 永远要问的 3 个产品化问题
1. 个性还是共性（3+ 客户独立出现？）
2. 泛化代价是否小于收益
3. 能否被不会写代码的人使用

|---|---|---|---|

### 5 句信条
1. 在错误的问题上，一切执行力都是浪费。
2. 价值不能继承，只能逐个验证。
3. 系统上线不是里程碑，客户团队改变工作方式才是。
4. 你创造的价值越大，影子越长（收入是价值的影子）。
5. 如果你不把现场学习转化为产品资产，你得到的只是一堆定制项目。
